## 🛠️ 1. ไฟล์ `data_prep/1_clean.py` (Data Cleaning & Feature Engineering)

**📌 หน้าที่ของโค้ด:** 
ดึงข้อมูลดิบ (`CAT_FINAL.csv`) มาล้างทำความสะอาด เปลี่ยนชื่อคอลัมน์ให้อ่านง่าย แปลงข้อมูล Text ให้เป็นตัวเลข (Encoding) และเช็ก Missing Value

**💡 ทำไมถึงเขียนโค้ดแบบนี้ (Code Rationale):**
1. **การใช้ Regex ในการเปลี่ยนชื่อคอลัมน์ (`re.sub` และ `re.match`):**
   * *ปัญหา:* ข้อมูลที่ Export มาจาก Google Form หรือ Excel มักจะมี "ช่องว่าง (Space)" ที่ไม่เท่ากัน บางช่องเว้น 1 วรรค บางช่องเว้น 2 วรรค หรือมีตัวอักษร Unicode ที่มองไม่เห็น
   * *วิธีแก้:* โค้ดถูกเขียนให้ใช้ Regular Expression `re.sub(r' {2,}', ' ', c)` เพื่อบีบอัดช่องว่างทั้งหมดให้เป็น 1 ช่องก่อน และใช้ Substring matching แทนการเทียบ String แบบเป๊ะๆ ทำให้โค้ดไม่มีวันพัง (Robust) แม้ Data จะถูกพิมพ์มาผิดเพี้ยน
2. **การแปลง Text List เป็น One-Hot Encoding (ส่วนของพันธุ์แมว / สิ่งที่อยากเพิ่มในแพ็กเกจ):**
   * *ปัญหา:* ลูกค้า 1 คนสามารถพิมพ์ตอบได้หลายอย่าง เช่น "ผสม, เปอร์เซีย" 
   * *วิธีแก้:* โค้ดถูกเขียนให้ใช้ `apply()` เพื่อเช็ก Keyword ก่อน แล้วค่อยแปลงเป็นคอลัมน์ 0/1 (Binary flag) แยกกัน เช่น `cat_thai=0, cat_inter=1, cat_mixed=1` ซึ่งเป็น Format ที่ Machine Learning เอาไปคำนวณได้ทันที
3. **จงใจ "ไม่ทำ StandardScaler" ในไฟล์นี้:**
   * *เหตุผล:* นี่คือการป้องกัน **Data Leakage** (ข้อสอบรั่ว) ตั้งแต่ระดับโครงสร้าง ถ้าเราเขียนโค้ด Scale ข้อมูล (หาค่าเฉลี่ยและส่วนเบี่ยงเบนมาตรฐาน) ตั้งแต่ไฟล์นี้ ข้อมูลชุด Test Set จะถูกเอามาหาค่าเฉลี่ยปนกับ Train Set ด้วย เราจึงทิ้งโค้ดไว้ให้เป็น Data ดิบๆ และไปทำ Scaling ในไฟล์ `4_supervised.py` แทน

## 🎯 2. ไฟล์ `data_prep/2_target.py` (Target Engineering)

**📌 หน้าที่ของโค้ด:** 
สร้างตัวแปรเป้าหมาย (Target Variable) ชื่อ `target_buy` ซึ่งเป็นตัวเลข 0 หรือ 1 เพื่อเตรียมส่งให้โมเดล Supervised Learning ทายผล

**💡 ทำไมถึงเขียนโค้ดแบบนี้ (Code Rationale):**
1. **เปลี่ยน Likert Scale เป็น Binary (0 และ 1):**
   * *ปัญหา:* เดิมทีลูกค้าให้คะแนนความอยากซื้อ (1 ถึง 5) หรือบางทีเราอาจอยากทำนายว่า "เขาจะชอบ Option ไหนมากที่สุดจาก 10 Option" (10-Class Classification)
   * *วิธีแก้:* ด้วยจำนวนข้อมูลเพียง 148 แถว ถ้าเราเขียนโค้ดให้ทายผล 5 ระดับ หรือ 10 Option ข้อมูลในแต่ละ Class จะมีแค่ ~10 กว่าแถว ซึ่งน้อยเกินกว่าที่โมเดลใดๆ ในโลกจะเรียนรู้ได้ โค้ดจึงถูกออกแบบให้ยุบรวมข้อมูล (Binarization) โดยตัด Threshold ที่คะแนน 4 (เห็นด้วยขึ้นไป) ให้เป็น 1 (ซื้อ) และต่ำกว่า 4 เป็น 0 (ไม่ซื้อ)
2. **มีระบบแจ้งเตือน Class Imbalance อัตโนมัติ:**
   * โค้ดมีการเขียนดักไว้ว่า `if minority_pct < 20:` ให้ปริ้นท์ `WARNING` แจ้งเตือน Data Scientist ว่าข้อมูลฝั่งใดฝั่งหนึ่งน้อยเกินไป (Imbalance) ต้องระวังตอนรันโมเดล

## 🔍 3. ไฟล์ `analysis/3_eda_unsupervised.py` (EDA & Clustering)

**📌 หน้าที่ของโค้ด:** 
คำนวณสถิติพื้นฐาน, สร้างกราฟ Heatmap/Bar chart, รัน K-Means Clustering, ทำ PCA และหา Anomaly

**💡 ทำไมถึงเขียนโค้ดแบบนี้ (Code Rationale):**
1. **การตั้งค่า `matplotlib.use('Agg')` ที่บรรทัดบนสุด:**
   * *เหตุผล:* โค้ดนี้ถูกออกแบบมาเพื่อรองรับการรันบน Server หรือ CI/CD Pipeline (ซึ่งมักจะไม่มีหน้าจอ UI) การเซ็ตเป็น `Agg` จะสั่งให้ Python "ไม่ต้องพยายามเด้งหน้าต่างกราฟขึ้นมาโชว์" แต่ให้วาดรูปใน Memory แล้ว `savefig()` ลงโฟลเดอร์ `output_plots/` ทันที ป้องกันโค้ดพัง (Crash) เวลารันบน Cloud
2. **การแยก Feature ตอนทำ Clustering:**
   * *หลักการ:* ในตัวแปร `cluster_features` เราเขียนโค้ดให้หยิบเฉพาะ "คุณสมบัติของอาหารและบรรจุภัณฑ์ (Food & Pkg attributes)" มาทำ K-Means
   * *เหตุผล:* เราตั้งใจ **ไม่เอา** คะแนน `opt_buy` ของทั้ง 10 Option มารวม เพราะถ้าเอามารวม K-Means จะจัดกลุ่มคนตาม "Option ที่ชอบ" ทันที ซึ่งเราไม่ได้อยากรู้ว่าใครชอบ Option ไหน แต่เราอยากรู้ว่า **"ลึกลงไปในจิตใจ เขาให้ความสำคัญกับอะไร (เช่น รสชาติ หรือ ความหรูหรา)"**
3. **การทำ PCA (Principal Component Analysis):**
   * *เหตุผล:* ข้อมูลของเรามีหลายสิบมิติ มนุษย์ไม่สามารถมองเห็นกราฟ 10 มิติได้ โค้ดส่วน PCA จึงถูกเขียนมาเพื่อ "บีบอัด (Dimensionality Reduction)" ข้อมูลทั้งหมดให้เหลือแค่แกน X (PC1) และแกน Y (PC2) เพื่อให้เราพล็อตจุดลงบน Scatter Plot 2 มิติ และใช้ตาเปล่าตรวจสอบได้ว่า K-Means แบ่งกลุ่มได้ขาดจากกันจริงหรือไม่

## 🤖 4. ไฟล์ `models/4_supervised.py` (Predictive Modeling)

**📌 หน้าที่ของโค้ด:** 
สร้างโมเดล Machine Learning เพื่อทายผล `target_buy` เปรียบเทียบประสิทธิภาพ และดึง Feature Importance ออกมาอธิบายผล

**💡 ทำไมถึงเขียนโค้ดแบบนี้ (Code Rationale):**
1. **การใช้ `Pipeline` จาก Scikit-Learn:**
   * *โค้ด:* `Pipeline([('scaler', StandardScaler()), ('model', RandomForestClassifier(...))])`
   * *เหตุผล:* นี่คือหัวใจสำคัญของการเขียนโค้ดระดับ Production (MLOps) ถ้าเราแยกคำสั่ง `scaler.fit()` เดี่ยวๆ มันมีความเสี่ยงสูงมากที่คำสั่งยิบย่อยจะเกิด Data Leakage การจับมัดรวมใส่ `Pipeline` รับประกันทางคณิตศาสตร์ว่า Data จะถูก Transform เฉพาะก้อน Train Set เสมอ ทั้งในช่วง Train ปกติและช่วง Cross-Validation
2. **การใช้ `StratifiedKFold` สำหรับการทดสอบ (Cross-Validation):**
   * *ปัญหา:* ข้อมูลเรามีคนตอบ "ซื้อ (1)" ถึง 72% ถ้าเราสุ่มแบ่งข้อมูลแบบปกติ (Random K-Fold) อาจมีบางรอบที่ข้อสอบ (Test Fold) ดันมีแต่คนตอบว่า 1 ล้วนๆ โมเดลก็จะประเมินผลเพี้ยน
   * *วิธีแก้:* โค้ดใช้ `StratifiedKFold` เพื่อล็อค (Lock) สัดส่วนให้ทุกๆ Fold มีคนตอบ "ซื้อ" 72% และ "ไม่ซื้อ" 28% เท่ากันเป๊ะๆ ทำให้คะแนนประเมินเสถียรที่สุด
3. **การใช้ `class_weight='balanced'`:**
   * *เหตุผล:* ฝังพารามิเตอร์นี้เข้าไปใน Logistic Regression และ Random Forest เพื่อสั่งให้โมเดล "ปรับสมการคณิตศาสตร์" ให้ความสำคัญกับคลาสส่วนน้อย (คนไม่ซื้อ 28%) มากขึ้นชดเชยกับจำนวนแถวที่น้อยกว่า
4. **การเขียนโค้ดแบบ Dictionary Mapping (`models = {}`):**
   * *เหตุผล:* โค้ดถูกเขียนให้เก็บโมเดลทั้ง 3 ตัวไว้ในตัวแปร Dictionary แล้วใช้ลูป `for name, pipeline in models.items():` แทนการเขียนโค้ดรันโมเดลซ้ำๆ กัน 3 รอบ (DRY Principle - Don't Repeat Yourself) ทำให้โค้ดสั้นลง อ่านง่าย และถ้าอยากเพิ่มโมเดลตัวที่ 4 อย่าง XGBoost ก็แค่เติมโค้ดบรรทัดเดียวเข้าไปใน Dictionary โมเดลใหม่ก็จะถูกเทรนและประเมินผลร่วมด้วยทันที
